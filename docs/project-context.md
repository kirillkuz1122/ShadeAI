## 4. Нюансы, которые учитывать в следующих задачах

1. **TASK-01 — исправлено имя ключа.** Settings.api_key использует alias `SHADE_API_KEY`, без значения по умолчанию. Окружение перекрывает `.env`; `API_KEY` больше не используется. `python -m app.setup` создаёт ключ, но не запускает Core и не меняет корректный существующий ключ. Минимум 32 ASCII-символа без пробелов.
2. **TASK-01 — исправлена установка.** [requirements.txt](../core/requirements.txt) содержит зависимости приложения, [requirements-dev.txt](../core/requirements-dev.txt) — дополнение для тестов/ruff. Прямые версии закреплены, транзитивные полностью не зафиксированы. LLM-зависимости отдельные. Docker включает пустой шаблон и приложение, ключ передаётся снаружи.
3. **TASK-02 — тесты изолированы.** [conftest.py](../core/tests/conftest.py) в pytest_configure меняет рабочую директорию и настройки до импорта Settings/engine; fixtures дают отдельную SQLite-БД на API-тест, MockTransport для HA и запрет DNS/TCP. Параметры из рабочего `.env` и окружения не используются. Движок освобождается через portal TestClient до закрытия event loop. Несколько клиентов одновременно в одном процессе не предусмотрены, поскольку исходный Core использует общие настройки/engine. Дальнейшие API-тесты писать через fixtures client/auth_headers/ha_mock и дополнять mock.
4. **TASK-03/09 — сборка, транспорт и подключение.** Импорт Composable исправлен; APK и экран проверены на эмуляторе. Manifest подключает [Network Security Config](../android/app/src/main/res/xml/network_security_config.xml): HTTP только для точных адресов 192.168.1.100, 10.0.2.2, 127.0.0.1, localhost, shade.local; HTTPS со штатной проверкой сертификатов. Для другого IP добавить конкретный адрес и пересобрать APK либо использовать доверенный HTTPS. [ShadeApi.kt](../android/app/src/main/java/com/shadeai/app/core/network/ShadeApi.kt) теперь добавляет Bearer к защищённым запросам; настройка ключа реализована в TASK-09, health без Bearer. Разрешение уведомлений включается вручную. Локальные инструменты JDK 17/SDK настроены, SDK в android/.gradle/, команда в [инструкции](../android/README.md); SDK/Gradle-кэш/APK не входят в git. При конфликте старого ANDROID_SDK_ROOT использовать env -u ANDROID_SDK_ROOT.
5. **TASK-05 — правила приёма.** API/хранение описаны в [контракте](api-spec.md#41-уведомления-notifications--реализовано-в-task-05). POST возвращает stored/duplicate/skipped без вызова заглушки/шины сырого текста. event_id — стабильный UUID отправителя; без него SHA-256 нормализованных app/title/text/time/priority, одинаковые события в один момент неразличимы. Повтор UUID с другим содержимым даёт 409. Статус skipped с id=null — окончательный пропуск; DTO Android это допускает. Приём фильтрует до записи, но Android-фильтрация перед Room ещё TASK-10/11. Серверные allowlist/слова кодов консервативны, а не универсальный NLP-классификатор. Не включать банки/мессенджеры ради теста доставки.
6. **TASK-11/12 — надёжность телефона.** Буфер синхронизируется при onListenerConnected; повтора при восстановлении Wi-Fi и backoff нет. Ошибки отправки игнорируются, отправленные строки Room не очищаются. Жизненный цикл и конкурентное форматирование времени требуют проверки.
7. **Контракт и ТЗ.** В TASK-01 architecture.md согласован с Bearer из AGENTS.md/api-spec.md/кода. Генерация ключа реализована отдельной командой настройки, а не автоматически в Uvicorn/systemd. Остальные маршруты, config.yaml и полноценная настройка разрешений/источников Android пока требования.
8. **Развёртывание веба.** Vite проксирует /api на localhost:8000 только в dev-режиме. FastAPI не раздаёт web/dist; production-сервер и прокси нужно реализовать в TASK-08.
9. **БД — схема только через миграции.** Новые изменения оформлять новой ревизией и моделью; старые ревизии не импортируют текущие модели. Lifespan делает upgrade head через run_sync; CLI из core/ — python -m alembic upgrade head/current/check. DB_URL общий с сервером. Сначала остановить Core и сделать копию через SQLite Backup API; core/backups/ игнорируется. Не применять stamp head. create_db_engine задаёт WAL/FK/BEGIN и hide_parameters. Текущий head — 0004_event_journal; 0003 перестраивает notifications_raw, 0004 — events_log с сохранением полей/ID и добавлением индексов/AUTOINCREMENT. Дальнейшая проверка приватности может удалить недопустимые/просроченные/повторные legacy-строки и очищает прежние JSON; это отдельный шаг после миграции.
10. **Очистка уведомлений.** NOTIFICATION_RETENTION_DAYS=30 (1..365); NOTIFICATION_ALLOWED_APPS — JSON-список доверенных служебных пакетов, пустой запрещает всё. До приёма запросов cleanup проверяет legacy пакетами 256; затем периодическая задача каждые 3600 секунд удаляет просроченное и отменяется в shutdown. GET скрывает просроченное/непроверенное сразу, не дожидаясь задачи. Логическое удаление не уничтожает старые копии и остатки страниц SQLite/WAL. После изменения политики сначала сделать копию. Новые ENV-поля включены в изоляцию pytest.

11. **TASK-06 — HA/audit.** Получать общий client через app.state/get_ha_client. Все команды — через execute_command: без pending нет отправки; БД не удерживается во время сети. Success/accepted — принятие сервиса HA; new_state читается отдельным GET, может быть null. Автоповтора/идемпотентности POST нет, timeout мог наступить после действия. При рестарте pending становится interrupted/unknown без повторной отправки. GET /events показывает только команды HA и проецирует безопасные поля, params/ответы/токены не сохраняются. EVENT_RETENTION_DAYS=90, чистка на старте и ежечасно; DeviceState/кэш/WebSocket остаются TASK-14.
12. **TASK-06 — диагностика/логи.** Health: SELECT 1 и HA ping, HTTP 200/ok или degraded при отказе HA, 503/error при отказе БД; не integrity check. Размер — main+WAL, LLM/worker/analytics отсутствуют. HA_TIMEOUT_SECONDS=5 ограничивает каждый обмен, ping также 2 секунды; общий client без redirect/proxy env, HTTPS со штатной проверкой. LOG_DIR=./logs, 1 MiB + 3 архива, файлы 600 при каждой ротации; папка создаётся 700, существующую владелец проверяет сам. Uvicorn console logs пока отдельно. Все ENV изолированы в fixtures.

13. **TASK-07 — веб.** useResource обслуживает независимые ресурсы: ключ явно передаётся в API-методы, запросы отменяются/не применяются после смены страницы/фильтра/ключа. Fetch no-store с 12-секундным таймаутом; опрос через 10 секунд после окончания, без перекрытия, пауза скрытой вкладки, обновление по online/visibility. 401 очищает список, временная ошибка оставляет последние данные с временем. При смене ключа protected-компонент перемонтируется и закрывает запись. Health принимает структурированный 503 Core как диагностические данные. Key хранится в localStorage, ошибка storage не ломает запуск/работу. Стенд и сценарии — [Web README](../web/README.md#воспроизведение-браузерной-проверки). Стенд использует core/.pytest_cache; не запускать одновременно с pytest, очищающим этот каталог.

14. **TASK-09 — Android.** ServerAddress нормализует корень/путь /api/v1/, запрещает credentials/query/fragment/иной путь; UI проверяет Network Security Config до сети. SavedConnection и UiState скрывают секреты в toString; ключ не попадает в SavedState. ServerPrefs хранит AES-GCM шифротекст и IV, AAD=нормализованный URL, ключ шифрования в Android Keystore; записи синхронизированы и атомарны через commit на IO. Пустое поле сохраняет прежний ключ только для прежнего адреса, новый URL требует нового ввода. При повреждении — безопасная ошибка, без молчаливого сброса; удалить/ввести заново. API получает явный снимок настроек, не передаёт ключ в health, не следует redirect, не использует proxy/автоповтор; таймауты 3/5/5/10 секунд. ViewModel отменяет старую проверку и защищён generation от её позднего результата. Служебный POST не использует Room и не доказывает перехват/доставку в фоне. Разрешения/источники/Room UUID/повторы — TASK-10–12. APK/SDK/логи/ключи не коммитить. Стенд и скрипт — [Android README](../android/README.md#проверки-без-физического-телефона).
