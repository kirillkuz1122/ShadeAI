## 1. Уточнения пользователя и принятые правила

- Документация — **ТЗ и целевая архитектура**. Сейчас написан скелет и часть инфраструктуры. Отсутствие запланированной функции само по себе не означает ошибку документации.
- Существующий код не равен готовому компоненту. Отдельно фиксировать наличие реализации и проверку поведения. Успешные тесты Core не подтверждают Android, LLM или управление физическим домом.
- Проектные планы, задачи, заметки и память хранить в папке проекта, а ссылки на них поддерживать в AGENTS.md. Новая сессия должна продолжаться по файлам репозитория без личной памяти агента и старого чата.
- По прямому указанию пользователя после каждой завершённой задачи делать отдельный коммит и push. Разрешение сохраняется для следующих задач; проверять staged-файлы и не отправлять секреты/сборки.
- Ответы, документация и сообщения коммитов — на русском. Обязательные ограничения: локальная работа без облачных API в рантайме, Raspberry Pi 5 с 4 GB RAM, минимальные зависимости и защита чувствительных данных.
- index.html и visitka/ — отдельная визитка. Рабочий дашборд расположен в web/; эти части не смешивать.

## 4. Нюансы, которые учитывать в следующих задачах

1. **TASK-01 — исправлено имя ключа.** Settings.api_key использует alias `SHADE_API_KEY`, без значения по умолчанию. Окружение перекрывает `.env`; `API_KEY` больше не используется. `python -m app.setup` создаёт ключ, но не запускает Core и не меняет корректный существующий ключ. Минимум 32 ASCII-символа без пробелов.
2. **TASK-01 — исправлена установка.** [requirements.txt](../core/requirements.txt) содержит зависимости приложения, [requirements-dev.txt](../core/requirements-dev.txt) — дополнение для тестов/ruff. Прямые версии закреплены, транзитивные полностью не зафиксированы. LLM-зависимости отдельные. Docker включает пустой шаблон и приложение, ключ передаётся снаружи.
3. **TASK-02 — тесты изолированы.** [conftest.py](../core/tests/conftest.py) в pytest_configure меняет рабочую директорию и настройки до импорта Settings/engine; fixtures дают отдельную SQLite-БД на API-тест, MockTransport для HA и запрет DNS/TCP. Параметры из рабочего `.env` и окружения не используются. Движок освобождается через portal TestClient до закрытия event loop. Несколько клиентов одновременно в одном процессе не предусмотрены, поскольку исходный Core использует общие настройки/engine. Дальнейшие API-тесты писать через fixtures client/auth_headers/ha_mock и дополнять mock.
4. **TASK-03 — сборка и транспорт / TASK-09 впереди.** Импорт Composable исправлен; APK и экран проверены на эмуляторе. Manifest подключает [Network Security Config](../android/app/src/main/res/xml/network_security_config.xml): HTTP только для точных адресов 192.168.1.100, 10.0.2.2, 127.0.0.1, localhost, shade.local; HTTPS со штатной проверкой сертификатов. Для другого IP добавить конкретный адрес и пересобрать APK либо использовать доверенный HTTPS. [ShadeApi.kt](../android/app/src/main/java/com/shadeai/app/core/network/ShadeApi.kt) ещё не добавляет Bearer, настройка ключа отсутствует. Разрешение уведомлений включается вручную. Локальные инструменты JDK 17/SDK настроены, SDK в android/.gradle/, команда в [инструкции](../android/README.md); SDK/Gradle-кэш/APK не входят в git. При конфликте старого ANDROID_SDK_ROOT использовать env -u ANDROID_SDK_ROOT.
5. **TASK-05 — смысл ответа и приватность.** POST notifications возвращает `queued`, но настоящей очереди нет. Результат заглушки не записывается в category/extracted_data/is_processed. GET total — размер страницы. Сейчас текст сохраняется без редактирования, хотя Android-список включает банки и мессенджеры; правила из архитектуры ещё предстоит реализовать.
6. **TASK-11/12 — надёжность телефона.** Буфер синхронизируется при onListenerConnected; повтора при восстановлении Wi-Fi и backoff нет. Ошибки отправки игнорируются, отправленные строки Room не очищаются. Жизненный цикл и конкурентное форматирование времени требуют проверки.
7. **Контракт и ТЗ.** В TASK-01 architecture.md согласован с Bearer из AGENTS.md/api-spec.md/кода. Генерация ключа реализована отдельной командой настройки, а не автоматически в Uvicorn/systemd. Остальные маршруты, config.yaml и сопряжение Android пока требования.
8. **Развёртывание веба.** Vite проксирует /api на localhost:8000 только в dev-режиме. FastAPI не раздаёт web/dist; production-сервер и прокси нужно реализовать в TASK-08.

## 5. Подтверждённые проверки и ограничения

- **Core (TASK-02):** **29 passed, 1 warning** на Python 3.14.7 обычной командой pytest и при повторном запуске из каталога с синтетическим некорректным `.env`/окружением. Контрольные `.env` и SQLite не изменились (сравнены SHA-256); два теста БД проходят в обратном порядке. Проверены 12 API-сценариев и 17 проверок настройки/CLI. Это не проверка успешного управления физическим устройством. Чистая установка Python 3.11 и 22 теста на ней подтверждены ранее в TASK-01.
- **Установка и запуск:** зависимости установлены с нуля в `core/.pytest_cache/task01-venv`, `pip check` успешен. Uvicorn запущен с созданным тестовым `.env`, выполнены реальные HTTP-запросы. Docker-образ `shade-core:task01` собран и запущен с внешним `.env`; рабочий `.env`, pytest и llama_cpp отсутствуют в образе. Тестовый сервер и контейнер остановлены после проверки. Все критерии TASK-01 описаны в [отчёте](reports/task-01.md).
- **Линтер:** `ruff check app tests` и `ruff format --check tests` — успешно.
- **Сетевая защита:** отдельный временный probe-тест пытался открыть TCP-соединение и перехватывал AssertionError. Запуск ожидаемо отклонён в teardown fixtures; реальное соединение не выполнялось. Этот probe не входит в постоянный набор 29 тестов и удалён после проверки.
- **Веб (предыдущая проверка):** `cd web && npm run build` — успешно; проверены TypeScript и сборка Vite, не взаимодействие в браузере. В TASK-01–02 веб-код не менялся.
- **Android (TASK-03):** assembleDebug + lintDebug успешны, 0 ошибок и 27 предупреждений lint. APK 9 727 512 байт, подпись v2 проверена; SHA-256 и версии инструментов — в [отчёте](reports/task-03.md). Эмулятор AOSP Android 15/API 35/x86_64 с профилем Pixel 2 запускает приложение, получает health от отдельного тестового Core через adb reverse, сохраняет адрес после force-stop. HTTP к 127.0.0.2 блокируется политикой Android; после возврата 127.0.0.1 health успешен. Падений приложения в crash log нет. Тестовый Core и эмулятор остановлены; рабочий .env/БД не использовались.
- **Документация:** 27 карточек, TASK-01–02 закрыты с отчётами, остальные открыты; для TASK-03 записан результат и оставшийся аппаратный критерий. В TASK-03 проверены 73 локальные ссылки в пяти изменённых документах и git diff --check. Задачи, контекст, отчёты и снимок эмулятора находятся в docs/. Временные файлы проверки создавались в игнорируемых каталогах проекта и удалены после проверки; SDK, Gradle-кэш, AVD и APK сохранены локально для дальнейшей работы.
- **Не проверены:** физический Android-телефон и доставка уведомлений, реальные HA-устройства, Pi, RAM/скорость LLM, голос и длительная эксплуатация. TASK-03 открыта только по аппаратной приёмке; TASK-04–27 не выполнялись.
- В песочнице pytest зависал в TestClient.__enter__/AnyIO portal. Вне песочницы 29 тестов прошли. Причина ограничения окружения не установлена; не считать это доказательством ошибки Core. Docker daemon также доступен только вне песочницы, sudo не требуется.
- В текущем окружении тесты выдают предупреждение Starlette об устаревшем использовании httpx. Не менять зависимости только ради предупреждения без отдельной проверки совместимости.

Штатная изолированная проверка из корня проекта:

```bash
cd core
.venv/bin/python -m pytest -q
.venv/bin/ruff check app tests
```

Ключи, БД и ответы HA настраиваются fixtures; предварительная настройка рабочего `.env` и запуск HA не требуются. Временные данные pytest по умолчанию удаляются после завершения; `--basetemp` поддерживается, включая относительный путь.
