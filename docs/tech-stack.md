# Технологический стек Shade AI

Документ содержит подробное описание технологий, библиотек, архитектурных решений и аппаратных средств, используемых при разработке и эксплуатации персональной интеллектуальной экосистемы **Shade AI**.

---

## 1. Backend (Серверная часть)

Серверное ядро Shade AI отвечает за оркестрацию сервисов, взаимодействие с LLM, интеграцию с платформой умного дома и предоставление REST/WebSocket API для клиентских приложений.

| Компонент | Технология | Обоснование выбора и ключевые преимущества |
| :--- | :--- | :--- |
| **Язык разработки** | **Python 3.11+** | • Высокая скорость разработки и богатая экосистема AI/Data Science.<br>• Существенные оптимизации производительности виртуальной машины (PEP 659, faster CPython).<br>• Нативная поддержка типизации и асинхронности. |
| **Веб-фреймворк** | **FastAPI** | • Нативная асинхронность (`asyncio`) с высокой пропускной способностью.<br>• Автоматическая валидация данных и сериализация через Pydantic v2.<br>• Автогенерация интерактивной документации OpenAPI (Swagger/ReDoc). |
| **ASGI-сервер** | **Uvicorn** | • Легковесный, высокопроизводительный асинхронный сервер на базе `uvloop` и `httptools`.<br>• Минимальное потребление памяти и низкие задержки при обработке запросов. |
| **Управление зависимостями** | **Poetry / pip** | • Строгая фиксация версий зависимостей через `poetry.lock`.<br>• Изоляция виртуальных окружений.<br>• Удобная сборка и детерминированный запуск в production. |

## 2. База данных и хранение данных

Для хранения состояния, логов событий, структурированных данных из уведомлений и настроек выбран легковесный реляционный стек с асинхронным доступом.

| Компонент | Технология | Назначение |
| :--- | :--- | :--- |
| **СУБД** | **SQLite** | Встраиваемая, бессерверная реляционная база данных |
| **ORM** | **SQLAlchemy 2.0 (async)** | Объектно-реляционное отображение с полной поддержкой `async/await` и статической типизации |
| **Миграции** | **Alembic** | Версионирование и автоматическое применение миграций схемы базы данных |

### Почему именно SQLite:
1. **Минимальное потребление памяти и CPU**: В условиях работы на Raspberry Pi 5 (4GB RAM) критически важно экономить оперативную память для моделей искусственного интеллекта. SQLite не держит отдельный фоновый процесс и потребляет считанные мегабайты.
2. **Бессерверная архитектура**: База хранится в локальном файле, нет накладных расходов на сетевой стек и администрирование СУБД (PostgreSQL/MySQL).
3. **Режим WAL (Write-Ahead Logging)**: Обеспечивает одновременное неблокирующее чтение несколькими потоками/процессами параллельно с записью, что устраняет проблемы с конкурентным доступом.
4. **Простота резервного копирования**: Бэкап базы сводится к простому атомарному копированию одного файла (или выполнению `.backup` команды), что упрощает автоматические сценарии обслуживания.
5. **Идеальное соответствие масштабу**: Для системы с одним пользователем и умеренным потоком IoT-событий производительности SQLite более чем достаточно (поддерживает тысячи транзакций в секунду).

## 3. Искусственный интеллект (AI / LLM)

Компонент ИИ предназначен для локального анализа неструктурированной информации без передачи конфиденциальных персональных данных во внешние облачные сервисы.

### Среда инференса (Inference Engine)
- **llama.cpp / Ollama**:
  - Высокооптимизированный C++ бэкенд с поддержкой векторных инструкций ARM NEON.
  - Поддержка современных форматов квантования моделей (GGUF: Q4_K_M, Q5_K_M).
  - Эффективное использование RAM/CPU без необходимости дискретного GPU.
  - Удобный REST API (при использовании Ollama) или прямой Python/C++ биндинг.

### Модели-кандидаты (для Raspberry Pi 5, 4GB RAM)

| Модель | Параметры / Квантование | Потребление RAM | Особенности и преимущества |
| :--- | :--- | :--- | :--- |
| **TinyLlama 1.1B** | 1.1 млрд / Q4_K_M | ~700 MB | • Сверхбыстрый отклик на CPU.<br>• Минимальный отпечаток в RAM, оставляет максимум памяти системе.<br>• Подходит для простых классификаций и бинарных решений. |
| **Gemma 2B** | 2 млрд / Q4_K_M | ~1.5 GB | • Хороший баланс скорости и качества понимания языка.<br>• Качественная работа с инструкциями и извлечением сущностей.<br>• Оптимизирована архитектура внимания. |
| **Phi-2 2.7B** | 2.7 млрд / Q4_K_M | ~1.8 GB | • Высокое качество логического вывода и понимания контекста для своего размера.<br>• Превосходно справляется со сложным синтаксическим анализом и структурированным JSON-выводом. |

### Задачи локальной LLM:
- **Парсинг уведомлений**: Преобразование неструктурированного текста мобильных пушей (банки, мессенджеры, сервисы доставки) в стандартизированные события.
- **Извлечение сущностей (NER)**: Выделение временных меток, сумм, локаций, отправителей, действий и ключевых триггеров.
- **Классификация**: Определение приоритета события (критическое, информационное, спам) и маршрутизация на нужный обработчик.

## 4. Умный дом и IoT

Уровень автоматизации отвечает за управление исполнительными устройствами и опрос датчиков физического окружения.

| Направление | Технология / Оборудование | Преимущества и роль |
| :--- | :--- | :--- |
| **Центральная платформа** | **Home Assistant** | Де-факто стандарт локальной домашней автоматизации. Огромная база интеграций, развитое сообщество, независимость от внешних вендорных облаков. |
| **Интерфейсы интеграции** | **HA REST API + WebSocket API** | • REST API: точечное выполнение команд и опрос состояний сущностей.<br>• WebSocket API: мгновенное получение событий об изменении состояний сенсоров в реальном времени. |
| **Промышленный контроллер** | **WirenBoard** | Высоконадежный контроллер автоматизации с поддержкой шины RS-485 / Modbus, встроенными реле и дискретными входами для критической проводной инфраструктуры. |
| **Беспроводные протоколы** | **Zigbee, Z-Wave, Wi-Fi** | • **Zigbee**: энергоэффективная mesh-сеть для автономных датчиков батареечного типа.<br>• **Z-Wave**: помехоустойчивый диапазон (868 МГц) для ключевых сенсоров и приводов.<br>• **Wi-Fi**: для высокоскоростных узлов и локальных медиа-устройств. |
| **Поддерживаемые устройства** | Свет, замки, датчики движения, климатические датчики | Комплексный мониторинг среды и исполнение автоматических сценариев (безопасность, микроклимат, освещение). |

## 5. Мобильное приложение (Android Client)

Клиентское приложение на базе Android выступает персональным интерфейсом пользователя, а также источником входящей телеметрии и уведомлений со смартфона.

| Уровень / Компонент | Технология | Обоснование выбора и преимущества |
| :--- | :--- | :--- |
| **Язык разработки** | **Kotlin** | Современный, лаконичный и безопасный (null-safety) официальный язык платформы Android с поддержкой корутин для асинхронного кода. |
| **Пользовательский интерфейс** | **Jetpack Compose** | Современный декларативный UI-фреймворк, ускоряющий верстку, снижающий объем шаблонного кода и упрощающий управление реактивным состоянием. |
| **Архитектурный паттерн** | **MVVM (Model-View-ViewModel)** | Четкое разделение ответственности, тестируемость бизнес-логики и сохранение состояния при смене конфигурации экрана. |
| **Перехват уведомлений** | `NotificationListenerService` | Системный Android API для фонового перехвата входящих уведомлений и отправки их на сервер Shade AI для интеллектуального анализа. |
| **Работа со звуком и речью** | `SpeechRecognizer` / `MediaRecorder` | Запись голосовых заметок и быстрый ввод команд с устройства через системные или нативные аудиоинтерфейсы. |
| **Сетевой стек** | **Retrofit / Ktor Client** | Типобезопасные асинхронные HTTP-клиенты с поддержкой JSON-сериализации (Kotlinx.serialization / Moshi) и WebSocket-соединений. |

## 6. Hardware (Аппаратное обеспечение)

Аппаратная платформа рассчитана на локальную автономную работу с минимальным энергопотреблением в режиме 24/7.

| Оборудование | Характеристики | Роль в системе |
| :--- | :--- | :--- |
| **Сервер** | **Raspberry Pi 5 (4GB RAM)** | • Основной хост для Shade Core, SQLite и локального инференса квантованных LLM.<br>• 4-ядерный процессор Cortex-A76 (2.4 GHz) обеспечивает необходимую скорость генерации токенов для компактных моделей. |
| **Операционная система** | **Raspberry Pi OS (64-bit) / Ubuntu Server** | • Оптимизированный Linux с 64-битным ARM-ядром (arm64/aarch64).<br>• Доступ к системным библиотекам и инструкциям ускорения вычислений. |
| **Контроллер** | **WirenBoard** | Аппаратный контроллер для проводных линий автоматизации, интерфейсов RS-485 и силовых реле. |
| **Zigbee координатор** | **TBD** *(например, Sonoff Zigbee 3.0 USB Dongle Plus)* | USB-адаптер с внешней антенной для координации беспроводной сети Zigbee датчиков и исполнителей. |

## 7. DevOps и Инфраструктура

Инструменты разработки, тестирования и развертывания ориентированы на надежность, воспроизводимость и простоту поддержки единственным разработчиком.

| Сфера | Инструмент | Преимущества и реализация |
| :--- | :--- | :--- |
| **Контроль версий** | **Git + GitHub** | Стандарт индустрии, безопасное хранение исходного кода, управление ветками и релизами. |
| **CI/CD** | **GitHub Actions** | Автоматизированный пайплайн: запуск линтеров (`ruff`, `mypy`), автоматическое тестирование (`pytest`), проверка сборки Compose-приложения. |
| **Управление сервисами** | **systemd (Linux)** | Нативная подсистема инициализации Linux на Raspberry Pi: автозапуск при включении, контроль падений, автоматический перезапуск сервисов, управление правами процесса. |
| **Логирование и мониторинг** | **Loguru** | Лаконичное и информативное логирование с цветным форматированием, автоматической ротацией файлов, сериализацией в JSON и обработкой исключений без рутинного конфигурирования. |
