## Результат

- POST принимает только проверенный объект: пакет 3..255 символов, title до 512, text до 8192, непустое содержимое; ISO-время с поясом и нормализацией UTC, допуск будущего 5 минут; фиксированные приоритеты. Тело ограничено 65 536 байт, включая поток без Content-Length. Ошибки не возвращают исходный input/ctx.
- Честные ответы: 201/stored, 200/duplicate, 200/skipped; category/processed_data не выдумываются, заглушка процессора и шина сырых данных не вызываются. Локальная LLM/очередь остаются следующими задачами.
- UUID event_id сохраняется отправителем на повторах. Для прежних клиентов без UUID — отпечаток нормализованных полей. Повтор получает прежний ID, другой текст с тем же UUID — 409. Уникальный индекс и SQLite ON CONFLICT защищают параллельную запись; [документация SQLAlchemy](https://docs.sqlalchemy.org/en/21/dialects/sqlite.html#insert-on-conflict-upsert).
- GET списка поддерживает limit/offset/category и общий total в одной read-транзакции; GET по целому ID возвращает объект или 404. ID после удаления не переиспользуется.
- Политика до INSERT: по умолчанию только три служебных пакета, известные банки/мессенджеры/SMS запрещены; уведомления с признаками кодов/паролей пропускаются целиком. Содержимое отказа не записывается и не отправляется в шину.
- Хранение по умолчанию 30 дней (1..365). Просроченное сразу скрыто из API; очистка при старте, раз в час и перед новым INSERT. Периодическая задача переживает ошибку и отменяется при завершении; параметры SQL скрыты. Для безопасных ошибок использован [механизм обработчиков FastAPI](https://fastapi.tiangolo.com/tutorial/handling-errors/#override-request-validation-exceptions).
- Ревизия 0003 добавляет ключ/хеш, индексы времени и AUTOINCREMENT через SQLite batch с сохранением полей/ID. Старые ревизии не менялись. После миграции legacy проверяется до приёма запросов пакетами по 256: недопустимые/старые/повторные записи удаляются, допустимые нормализуются; старый JSON/категории заглушки очищаются.
- Web-типы и методы синхронизированы, UI не расширялся. Android принимает nullable id и optional reason/event_id, использует Instant с точностью postTime; банки/мессенджеры удалены из исходного Allowlist. Авторизация и надёжная очередь телефона ещё не реализованы.

## Решения и ограничения

- Допуск — явный список доверенных служебных источников плюс консервативный поиск слов, а не универсальное распознавание приватного смысла. Код получения доставки тоже пропускается. Новые приложения добавляет владелец осознанно; имя пакета сообщает доверенный клиент, аттестации нет.
- Отпечаток старого клиента не различает полностью одинаковые события в один момент; для этого предусмотрен UUID. Его генерация/устойчивое хранение в Android остаются в задачах очереди телефона.
- Проверка legacy может удалить ранее записанные данные. Перед обновлением нужна копия; миграция схемы и применение политики — отдельные шаги. Логическое удаление не гарантирует уничтожения старых страниц WAL/SQLite и резервных копий.
- Фильтрация телефона перед Room, Bearer, повторы после потери сети, UI истории, реальный HA, LLM и Pi ещё не подтверждены.
