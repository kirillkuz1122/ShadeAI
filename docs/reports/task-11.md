# TASK-11 — форматы уведомлений, UUID и локальный буфер

Дата: 2026-10-18. База: `1621cea` (TASK-10). **Программная часть реализована и проверена на эмуляторе. Общий чекбокс TASK-11 открыт:** критерий сохранения/перезапуска на физическом телефоне пока не проверен. Пользователь разрешил продолжать доступную работу без телефона/Pi; повторно их не запрашивали.

## Что изменено

- [NotificationReader](../../android/app/src/main/java/com/shadeai/app/service/NotificationReader.kt) обрабатывает обычный/расширенный заголовок, BigText, InboxStyle, ticker, отсутствие одного поля и CharSequence со стилями. Проверяет все кандидаты/subtext/ticker на приватность до выбора; не обрезает длинный текст и не использует типизированные Bundle-getters, логирующие неверное значение. Неверные типы/пределы, сообщения MessagingStyle, признаки секретов, служебные уведомления и системная заглушка Android 15 пропускаются. Лимиты и приоритет выбора — в [Android README](../../android/README.md#форматы-идентичность-и-локальный-буфер-task-11).
- Новая [Room v2](../../android/app/src/main/java/com/shadeai/app/data/db/AppDatabase.kt) хранит UUID, хеш ключа Android/принятого содержимого, неизменяемые поля версии, PENDING/FAILED/SENT/SKIPPED и даты создания/подтверждения. Отдельная таблица notification_heads хранит последнюю принятую версию и active, без исходного key/tag/текста. Два callbacks с одинаковым ключом/title/text дают одну версию независимо от нового postTime. Изменение содержимого — новый UUID; удаление и новая публикация — новая история. Сверка активных ключей при подключении не импортирует старые уведомления.
- [Миграция 1→2](../../android/app/src/main/java/com/shadeai/app/data/db/BufferMigrations.kt) сохраняет ID, payload/postTime, sent→status и счётчик AUTOINCREMENT, включая пустую таблицу с удалёнными ID. Fallback с уничтожением данных убран. Схемы [v1](../../android/app/schemas/com.shadeai.app.data.db.AppDatabase/1.json)/[v2](../../android/app/schemas/com.shadeai.app.data.db.AppDatabase/2.json) экспортированы в Git. Старые строки остаются без event_id/sourceKey: новый UUID мог бы обойти прежний серверный отпечаток, а исходный Android key отсутствует. Повтор старой отправки сохраняет прежний режим, но сопоставление новых callbacks с историей v1 достоверно не восстанавливается.
- [NotificationCapture](../../android/app/src/main/java/com/shadeai/app/service/NotificationCapture.kt) отделяет durable-запись от ожидания сети. stateMutex защищает запись/политику, deliveryMutex — отправку и подтверждённое переключение источника; порядок захвата delivery→state. Перед отправкой перечитывается строка по ID, поэтому удалённый буфер не оживает из старого снимка. Сетевого ожидания внутри SQL-транзакции нет. После отмены сохраняется неподтверждённая строка, следующий запуск использует прежний UUID/payload.
- [Listener](../../android/app/src/main/java/com/shadeai/app/service/ShadeNotificationListener.kt) содержит одну сессию с отдельным обработчиком callbacks и одним отправителем, по 128 элементов в каналах. При disconnect/destroy сессия и каналы отменяются. В очереди не удерживаются StatusBarNotification/RemoteViews. При подключении sync берёт до 100 строк; дальнейшая надёжная доставка остаётся TASK-12.
- [Sender](../../android/app/src/main/java/com/shadeai/app/core/network/NotificationDelivery.kt) передаёт сохранённый UUID и Instant UTC. Только stored/duplicate с положительным ID дают SENT, skipped с id=null — SKIPPED; неполный/неизвестный ответ — FAILED. Нет ключа — PENDING, исключение попытки — FAILED без raw error, отмена не подделывает подтверждение. Маршруты Core не изменились; использование event_id описано в [api-spec.md](../api-spec.md#411-post-notifications--принять-уведомление).
- Добавлена ограниченная очистка: максимум 1000 строк, 2000 записей метаданных; неподтверждённое до 7 дней, подтверждённое до суток, метаданные до 7 дней. Очистка при проверке/подключении/синхронизации и записи, без нового фонового таймера. Удаление отправленного не удаляет сразу head, поэтому callback не создаёт новую доставку после очистки строки. При переполнении head сначала удаляется неактивное. Подробные пределы и возможные пропуски — README; гарантии доставки при любой нагрузке не заявляются.

Миграционные тесты создают реальную SQLite по экспортированной v1, проверяют payload/status/ID, закрытие/открытие, сохранение удалённого sequence и атомарный откат при конфликте с последующим успешным восстановлением. Новый тест не подключается к рабочей БД приложения. Другие тесты используют in-memory Room или отдельные task11-*.db; предыдущие настройки TASK-10/09 изолированы префиксами.

Буфер проверен на 20 конкурентных одинаковых записях; обновлении и удалении/repost; сохранении после закрытия БД; потере ответа и точном повторе запроса; записи во время сетевого ожидания; отмене запроса; terminal/7-дневной очистке и сохранении head; лимите 1000 и непереиспользовании ID; запрещённой отправке удалённой строки; сверке исчезнувших Android-ключей и лимите 2000 с приоритетом неактивных. Reader отдельно проверяет секрет в невыбранном варианте текста, формат Bundle, пределы, служебные флаги, MessagingStyle и локализованную заглушку.

## Системный путь без телефона

Использован AVD ShadeTask03API35 (AOSP Android 15, x86_64, Pixel 2), JDK 17, Gradle 8.10.2, AGP 8.7.3, SDK 35. [Синтетический издатель](../../android/checks/publisher/src/main/java/com/shadeai/fixture/PublisherActivity.kt) расширен форматами/обновлением/cancel; optional-модуль не зависит от Shade и не входит в обычную сборку. Реальный Ozon в AVD отсутствовал. Core запускался через [изолированный стенд](../../android/checks/core_server.py), с временной SQLite/синтетическим ключом, без рабочего .env/БД/HA.

1. Чистая настройка debug-приложения через UI, выбор Ozon; доступ listener выдан через adb. Уведомления публиковал отдельный APK через системный NotificationManager. Проверка UI выдачи/отзыва уже относится к TASK-10.
2. adb reverse удалён: BigText сохранён с UUID и FAILED при отсутствии связи. Повтор того же Android ID не создал строку, изменение текста создало вторую версию с другим UUID и неизменной первой строкой.
3. InboxStyle, ticker и только заголовок дали ещё три строки. Код в скрытом варианте, ongoing/local-only/group-summary не увеличили буфер; Core оставался пустым.
4. Force-stop сохранил все пять payload/UUID/postTime/статусов. После открытия приложения и явного rebind повтор текущей версии пропущен. Cancel/repost дал шестую строку с новым UUID.
5. После восстановления reverse и явного rebind Core получил шесть записей, Room стал SENT. Сверены набор UUID, title/text и исходное время в UTC. Повтор callback не добавил строк; отдельный точный HTTP-повтор первого payload дал duplicate без седьмой записи.
6. Crash log без FATAL EXCEPTION. Тестового API-ключа и синтетического текста кода нет в logcat; маркер кода отсутствует в снимке Room/его WAL. Все данные синтетические. Проверочный издатель, listener grant и reverse удалены в finally; Core/AVD остановлены после проверки. Снимки/логи/SDK/APK остались только в игнорируемых каталогах.

Воспроизведение — [Android README](../../android/README.md#проверки-task-11). Скрипт требует свежий Core, qemu и отсутствие установленного пакета Ozon, не заменяет реальные приложения и сбрасывает только debug-данные Shade в эмуляторе. Gradle и другой UI Automator не должны работать одновременно со сценарием.
