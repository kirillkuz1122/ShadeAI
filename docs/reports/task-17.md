# TASK-17 — схема и извлечение уведомлений

**Дата:** 2026-10-18. **База:** a6030ea. **Статус:** программная задача выполнена на компьютере. Qwen/ctx2048/2: 4/4 dev по категории/времени/размеченным сущностям, Core/worker/SQLite/API/restart/duplicate в offline namespace. Целевые ≥90%/≤4 с и Pi не подтверждены; отдельная оценка TASK-18 не заменяется четырьмя dev-примерами.

## Реализация

- Версия результата 1: processor=llm/llm=true, пять категорий delivery/transport/calendar/reminder/noise, отдельный распознанный priority, описательный intent, entities subject/location/service, time source/timezone/at/date/resolution. action_authorized всегда false, никаких HA-команд/параметров. Confidence не имитируется числом модели; finance/communication не расширяют разрешённые источники.
- Русский system prompt и три отдельные синтетические пары примеров отделены от JSON title/text (всего 8 сообщений). Модель получает JSON Schema; код независимо проверяет результат строгим Pydantic: типы/enum/длина/лишние поля, повтор ключа, обрезанный ответ и цитаты. Каждая непустая сущность должна буквально встречаться в title/text; исходный ответ при ошибке не сохраняется, LLM_BAD_RESPONSE без raw. Это не доказывает смысловую правильность классификации/цитаты — нужна TASK-18.
- Детерминированное время от timestamp уведомления и NOTIFICATION_TIMEZONE, default Asia/Yekaterinburg. Входной offset уже превращён в UTC при приёме. Поддержаны интервалы минут/часов/дней, сегодня/завтра/послезавтра, ISO/дд.мм.гггг с необязательным HH:MM. Короткая цитата голых часов дополняется сегодня/завтра/послезавтра только из единственного буквального контекста; при двух разных днях не угадывается. Без часов date_only, неизвестное/неоднозначный DST unresolved; не подставляется текущий день worker или выдуманная полночь.
- Явные NOTIFICATION_PROCESSOR=llm + LLM_ENABLED=true подключают к одному общему движку; default disabled/diagnostic сохранены. До claim worker ждёт загрузку, статус waiting_model/model_unavailable, pending и attempts=0 сохранены. Startup не расходует таймаут отдельного события. Runtime timeout/отмена/выход процесса перед следующим событием требуют явной reload; persistent ошибки ждут исправления/перезапуска. Terminal failed автоматически не повторяется.
- Success пишет проверенные JSON/category в прежний атомарный finish, транзакции во время inference нет. Обработчик не получает HAClient, quote/intent не вызывает действий. Ошибки LLM сохраняются только фиксированными кодами, Pydantic serialization warnings не могут отразить невалидный payload в логах. Схема БД/миграции не меняются. API/receipt обратно совместим, контракт обновлён.
