# TASK-16 — локальный движок и предварительные измерения

**Дата:** 2026-10-18. **База:** 8dc876b. **Статус:** программная часть и сравнение на компьютере выполнены; общая задача открыта до Pi. Проверен x86_64-компьютер; Pi 4 GB, общий RAM-бюджет с HA, охлаждение и автономная аппаратная приёмка отсутствуют.

## Что реализовано

- Заглушка заменена `LocalLLMEngine`/отдельным stdio runner. CPU-инференс, импорт optional-пакета и хеширование GGUF выполняются вне HTTP event loop. На старте Core модель загружается фоном, по умолчанию отключена. Один процесс/запрос, без очереди параллельных payload; LLM_BUSY при занятости.
- Локальный GGUF до 2 GiB, проверка magic, типизированный протокол ≤64 KiB, ограничение входа/ответа/контекста/потоков. Linux RLIMIT_AS ограничивает **виртуальную память процесса**, не RSS всех сервисов. По умолчанию 1024 токена, 2 CPU-потока, 128 выходных токенов, 2304 MiB; параметры ещё не являются профилем принятого Pi.
- Timeout/отмена завершают и reap дочерний процесс, включая отмену во время spawn. Повторная загрузка явная. Shutdown останавливает notification worker до модели и освобождает HA/БД после них. Ошибка модели не блокирует базовый API.
- Дочерний процесс не наследует секреты/API/HA/proxy/user PYTHONPATH; native stdout/stderr направлены в /dev/null, наружу только фиксированные коды. Python connect/DNS запрещён audit hook; используются локальный путь и offline env, GPU/RPC в проверяемой сборке выключены. Это не sandbox для произвольного нативного кода, для сетевой изоляции служит отдельный `--network none`-стенд. KV-cache не обещает криптографического стирания.
- Optional-зависимость закреплена `llama-cpp-python==0.3.36`; базовые requirements/Docker её не устанавливают. CPU build на рабочем компьютере: Python 3.14.8, CUDA/RPC OFF, 2 build jobs. Установка и pip check успешны.
- Подготовительный загрузчик использует pinned revision/размер/SHA-256 для обоих предусмотренных кандидатов, `.part`/flock/Range и атомарную публикацию только проверенного файла. Рабочие модели/parts/locks игнорируются git. Автоскачивания в runtime нет.
- Health показывает not_loaded/loading/ready/безопасный код; Web переводит состояния, не выдаёт сырой неизвестный код. `ready` не означает качество NLU, подключённый обработчик или привычки. В TASK-16 уведомления по-прежнему не обрабатываются реальной LLM: связь с worker — TASK-17.

## Проверки

- **205 passed, 1 warning**, Python 3.14.8; прежнее предупреждение Starlette/httpx. 18 новых проверок движка: отсутствие модели/disabled, границы, строгий RPC, отделение окружения, повторное использование, timeout/reload, cancel/spawn без сироты, concurrent BUSY, неверный/обрезанный ответ/EOF, context error и Core fallback. 7 проверок загрузчика — атомарность/повтор, Range206/200, неверный offset/хеш/размер, сохранение прежнего файла. Все pytest по-прежнему изолированы от рабочего `.env`, БД и TCP.
- Ruff и Web build успешны. Chromium с синтетическим Core: not_loaded→loading→ready→неизвестная ошибка, пояснение о незавершённых анализе/привычках, 320 px без overflow, raw-код/внешние запросы/JS-ошибки отсутствуют. Переходы health имитированы browser route; это не проверка нативного inference в UI. Скриншот игнорируется в web/output/playwright/task16-health.png.
- Реальный native-процесс с синтетическим повреждённым GGUF: LLM_LOAD_FAILED, health/приём/история Core продолжают работать. Стенд создаёт одноразовую SQLite и HA MockTransport, HTTP через ASGITransport.
- Обычный **Docker shade-core:task16 / Python 3.11.16**, `--network none`: LLM_DEPENDENCY_MISSING с синтетическим GGUF, приём/история Core работают. Образ действительно без optional-пакета, он не имитирует загрузку модели.
- TinyLlama скачана, размер/SHA-256 совпали с manifest. **Настоящий inference/HTTP/cancel/reload прошёл** через полный Core. Четыре профиля ниже измерены последовательно, по 8 русских классификационных smoke после отдельного warmup. Результаты всех примеров сохранены в [JSON](task-16-tinyllama.json). GGUF chat_template фактически присутствует и выбирается как chat_template.default; это не ошибочный fallback на llama-2.
- Qwen скачана/проверена по manifest, настоящий inference/HTTP/cancel/reload прошёл в `unshare -Urn` без сети. Четыре профиля измерены последовательно после TinyLlama, [полные результаты Qwen](task-16-qwen.json).

## Предварительные профили на компьютере

AMD Ryzen 5 5600H, x86_64, Python 3.14.8, llama-cpp-python 0.3.36 CPU. ctx — настроенный контекст, RSS — максимум дочернего процесса, p50 — полное время успешного RPC классификации; это не весь Core/HA и не Pi.

| ctx | threads | Верно, из 8 | p50, мс | Peak RSS, MiB |
| :--- | :--- | :--- | :--- | :--- |
| 1024 | 2 | 2 | 539.75 | 1128.05 |
| 1024 | 4 | 2 | 354.50 | 1195.21 |
| 2048 | 2 | 2 | 549.83 | 1220.64 |
| 2048 | 4 | 2 | 355.64 | 1220.55 |

Во всех случаях TinyLlama отвечала delivery на каждый из 8 текстов. Увеличение потоков ускоряет ответ на этом CPU, но не исправляет категорию. Файл весов около 638 MiB не означает такой же RSS. Для текущего русского промпта модель не принимается как пригодный NLU-кандидат; дальнейшая проверка выполняется с Qwen в TASK-17/18.

| Qwen ctx | threads | Верно, из 8 | p50 успешных RPC, мс | Peak RSS, MiB |
| :--- | :--- | :--- | :--- | :--- |
| 1024 | 2 | 6 | 686.16 | 1854.68 |
| 1024 | 4 | 6 | 479.49 | 1854.11 |
| 2048 | 2 | 6 | 698.05 | 1881.58 |
| 2048 | 4 | 6 | 486.04 | 1880.61 |

В первых трёх профилях Qwen приняла рекламу/обновление за reminder. В последнем после шести ответов процесс завершился: два последних примера LLM_PROCESS_EXITED включены в знаменатель, p50 рассчитана по шести успешным RPC. Причина native-выхода не установлена; этот профиль не принимается как устойчивый. Это не основание объявлять общий OOM или сбой Core.

**Для дальнейшей программной отладки предварительно выбран Qwen 2.5 1.5B Q4_K_M, ctx=2048, threads=2, RLIMIT_AS=2304 MiB.** Контекст нужен для схемы/русского промпта, 2 потока сохраняют ресурс Core и дали проход всех 8 запросов без выхода процесса. В классификационном benchmark max_tokens=64; полный структурированный разбор отдельно требует до 256 и проверяется TASK-17/18. Предварительный выбор на восьми примерах не подтверждает ≥90%, ≤4 с или длительную устойчивость. Путь модели включается явно, runtime по умолчанию выключен. Общие RAM/температура/скорость на Pi 4 GB остаются неизвестны.
