# TASK-18: отдельная модель для классификации уведомлений

Идея Кирилла от 16 ноября 2026 года, исследование по карточкам моделей. Загрузок,
замеров и изменений рабочего обработчика в этом срезе нет.

Проблема наблюдается в новом [замере](task-18-holdout-2026-11-16.json): 0/4
правильных категорий транспорта и 8/30 отказов проверок ответа. Классификатор
может помочь с такси, доставкой и рекламой. Он сам по себе не извлечёт адрес и
не исправит неподтверждённую цитату. В [TASK-19](task-19-native-staged-2026-11-16.json)
обе захваченные Android-записи Qwen отклонила; успешный контроль шёл через API.

| Кандидат | Что показывают первичные источники | Решение для опыта |
| --- | --- | --- |
| [Jev TypeSafe](https://docs.typesafe.ai/introduction) | Типизированный выбор, оценки и вероятности; документированный продукт использует API TypeSafe | Облачный API не подходит Zero-Cloud. Берём идею, не провайдера |
| [Laya](https://huggingface.co/convaiinnovations/laya) | Основной вариант настроен на английский | Для русских уведомлений не первый кандидат |
| [Laya Multilingual](https://huggingface.co/convaiinnovations/laya-multilingual), [экспорт ONNX](https://huggingface.co/verdict-models/laya-multilingual) | Локальный многоязычный классификатор; есть сторонний экспорт в ONNX. [CPU ONNX Runtime](https://onnxruntime.ai/docs/get-started/with-python.html) доступен для Linux ARM64 | Первый кандидат для сравнения; проверить конкретный граф, токенизатор, русский и суммарную память Pi, не подставлять GGUF в существующий Qwen runner вслепую |
| [CMF Decision](https://huggingface.co/infosave/cmf-decision) | Компактный отдельный формат, рантайм Cortiq и обученные сценарии; карточка помечена English | Запасной кандидат после доказательств русского качества и прогона на Pi ARM64 |
| [Clef-Flash](https://huggingface.co/Cloudflare/clef-flash) | Основан на Qwen3.5-9B | Не пробовать на Pi 4 GB: вариант 6,2 ГБ со скриншота уже слишком большой для нашего бюджета |

Место опыта — в worker после допуска/записи, перед извлечением. Выход маршрутизатора
ограничен пятью существующими категориями и вариантом «не уверен». Сначала его
прогноз только сравнивать с разметкой, не менять обработку/отправку. Сохранение
оригинала, строгая проверка цитат, нормализация даты в коде и запрет действий по
LLM-результату остаются. Низкая уверенность не должна выбрасывать уведомление.

Порядок: сравнить простой локальный вариант без новых весов с Qwen на dev; затем
отдельно проверить Laya Multilingual с теми же условиями и на новой необученной
русской выборке. Измерять полное совпадение полей, путаницу taxi/delivery/noise,
пропуски важных событий, долю вызовов Qwen, холодную/прогретую задержку и пиковую
память **Core + HA + процессы моделей** на Pi 4 GB. Карточки и размер весов
не подтверждают эти показатели. Включать новую зависимость только при выигранном
сравнении и сохранении Zero-Cloud; до проверки не держать два движка резидентно.
