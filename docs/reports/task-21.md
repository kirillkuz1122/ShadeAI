# TASK-21 — предложения сценариев и локальные подсказки

**Статус:** программная часть реализована; TASK-21 остаётся открытой. Исполнителя HA ещё нет (TASK-22). Реальный телефон, системные уведомления Android/Doze, Pi и единый конвейер с нативной LLM не проверены.

## Реализация

Core создаёт предложения только из актуальных профилей TASK-20 со score ≥0.75. Причина, окно, число дней и разброс доступны клиентам; score — эвристика, не вероятность. Устойчивый ID привязан к профилю. Отклонение и отключение сохраняются при пересчёте и перезапуске. До принятия требуется явно выбрать конкретную цель из `AUTOMATION_ALLOWED_LIGHTS` (по умолчанию пусто). Только light.turn_on/turn_off без произвольных параметров; смена условий или политики требует нового подтверждения. Недоступный/устаревший источник не даёт действующего разрешения.

Миграция 0008 добавляет правила, историю решений, ленту подсказок и постоянный feed_id. Решения accept/reject/disable проверяют версию, записываются атомарно; отключить можно и по прежней версии. История ограничена 1000 решениями/90 днями, правил максимум200. В API `enabled` означает действующее подтверждение, `executable=false`, `executor_status=not_implemented`: команды этим срезом не отправляются. Контракт GET/POST automations и GET hints добавлен в [api-spec.md](../api-spec.md#44-предложения-сценариев-и-локальные-подсказки--программная-task-21).

Подсказка о приходе требует свежего live off→on выбранного датчика, connected/checkpoint, согласованного времени, отсутствия gap и существующей канонической обработанной доставки schema1. Snapshot/такси/невалидный результат сами по себе подсказку не создают. В ленте только общий kind, время и ID контекста, без личного текста. Один переход не дублируется; cooldown1час и один контекст/сутки. Хранение7дней/1000строк, независимый курсор каждого клиента. Никаких HA-команд из LLM/подсказки.

Web и Android показывают предложения, явный выбор цели, решения и историю, общий список подсказок. Частный контекст открывается отдельно по действию пользователя. Незнакомый формат не позволяет подтвердить действие;409 требует перечитать условия, POST автоматически не повторяется. Смена ключа/сервера и выход отменяют запросы и очищают данные. Дополнительно исправлен переход Android на другой Core во время STOP: ID/страница прежнего сервера не используются при возврате. Health веба теперь отдельно обозначает загруженную модель и аналитику.

Android: отдельный opt-in, POST_NOTIFICATIONS и системный канал, WorkManager15мин + ручная проверка, без FCM. В prefs только opt-in/revision/feed/cursor/фиксированный код паузы; ключ через Keystore/ServerPrefs, WorkManager Data без секретов. Смена revision останавливает прежнюю подписку; при первом включении/новой ленте старые подсказки не поднимаются. Стабильный notification tag и cursor подавляют повторы. Отправка уведомления и запись cursor **не атомарны**: после сбоя/ручного удаления возможен повтор; exactly-once не заявляется. Doze/производитель задерживают WorkManager, доставки в реальном времени нет.

## Проверки и найденные дефекты

- Core: **315 pytest**, Python3.14 и Python3.11 в существующем Docker-образе с `network none`, ruff app/tests/migrations/checks. Миграции/откат/metadata покрываются общими тестами. 18 проверок TASK-21: авторизация, явная цель, sticky-решения, смена политики, гонка двух решений, rollback, лимит тела, курсор, gaps/snapshot/часы, cooldown и retention.
- Найдена реальная гонка SQLite WAL: чтение с последующим повышением до writer могло дать BUSY_SNAPSHOT при параллельном collector/analytics/suggestions. Добавлен внутренний `sqlite_immediate` для этих коротких фаз записи до чтения, без сети/CPU внутри транзакции. Регрессия гонки проверяет10 повторов, disabled collector не становится disconnected. Обычный BEGIN сохранён для остальных операций.
- Настоящие Uvicorn/HTTP и HA WebSocket на loopback: 4 предложения, принятие/отклонение, live приход→одна подсказка, новый lifespan/та же SQLite сохраняет решения/feed_id, повторный приход не дублирует контекст, **0 HA-команд**. Результат — [task-21-loopback.json](task-21-loopback.json), стенд `core/checks/check_suggestions.py`. Контекст подготовлен синтетической валидной schema1, нативная LLM **не** запускалась. Первоначальная неполная legacy-fixture была сброшена штатной очисткой; стенд исправлен на канонические identity/hash, сервис исключает legacy-контекст.
- Android: **21 focused JUnit** TASK-19/21, настоящий Retrofit/Bearer/loopback MockWebServer, гонки revision/STOP/409, курсоры. Все production Kotlin/Compose исходники скомпилированы существующими компиляторами. `python android/checks/check_results_jvm.py --compile-app`; heap512MiB/128MiB, временные20 693 179байт AAR удалены. Это не полная Gradle/JVM suite, APK, KSP, manifest merge, lint или instrumented/OS-проверка. Два предупреждения deprecated allNetworks. В песочнице loopback запрещён, поэтому проверка выполнена вне неё; новые зависимости не скачивались.
- Web: build, Node processing/automations guards; Chromium с синтетическими routes: явная цель, accept/reject/disable/history,409 без повтора POST, общий hint/частный контекст по клику, неизвестный формат,401 очистка,320px, нет внешних запросов/JS-ошибок. Сценарий `web/checks/suggestions.js`; реальный сервер отдельно проверен Core-стендом.
