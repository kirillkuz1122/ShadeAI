# TASK-12 — надёжная доставка уведомлений Android

**Дата:** 2026-10-18. **База:** `2c146b3`. Коммит реализации определяется по TASK-12 в git log. Статус: выполнена на синтетическом AOSP API 35; приёмка телефона/фона и всего v0.2 остаётся TASK-13. Общие аппаратные критерии TASK-03/09/11 не закрыты.

## Реализация

- Отправка перенесена из сессии NotificationListener в CoroutineWorker, WorkManager **2.10.1**. Listener только сохраняет и будит очередь. Приложение не зависит от тестового publisher/прокси.
- Уникальная цепочка: максимум 100 строк и 45 секунд за запуск, затем следующая порция или задержка. Периодический recovery с минимальным интервалом 15 минут страхует запись перед гибелью процесса и гонку KEEP с окончанием worker. Это не гарантия задержки доставки.
- При полном отсутствии сетей HTTP не начинается, запись остаётся PENDING. Сетевой callback запускает новую проверку; INTERNET/VALIDATED не требуются. Наличие сети не равнозначно доступности Core.
- Room v3, новая миграция v2→v3, экспорт схемы. Старые UUID/payload/ID/sequence/heads/статусы сохраняются. Миграция v1→v2 не менялась, destructive fallback отсутствует. Добавлены attempts/lastError и единственная строка delivery_control.
- Ошибки связи/408/425/429/5xx задерживают всю очередь: 30 секунд, минута, две и далее до 6 часов. Новые события, рестарт и сетевые callbacks серверную задержку не сбрасывают. Пауза 401/403/config/TLS/неверного receipt действует до сохранения настроек. Ошибки 400/409/413/422 завершают только конкретную строку как REJECTED.
- Save/clear создаёт случайную несекретную revision и упорядочен с отправкой. Никакого хеша ключа в БД. В WorkManager Data нет ключа, URL или уведомления. Ошибки хранятся безопасными категориями, без ответов Core и исходных исключений.
- Строка и gate завершаются одной транзакцией. Если сохранение подтверждения не удалось, ошибка передаётся worker для backoff; повтор использует прежний UUID. SENT возможен только по stored/duplicate с положительным ID. Отменённая отправка остаётся неподтверждённой.
- Лимиты TASK-11 сохранены: 1000 строк/2000 heads, callbacks 128; неподтверждённое/heads до 7 дней, SENT/SKIPPED/REJECTED до суток. Перед HTTP повторно проверяются доступ/источник/приватность и существование строки.
- Контракт REST и исходники Core/Web не менялись; используется дедупликация TASK-05. LLM/алгоритм привычек не реализованы этим изменением.

Окружение: OpenJDK 17, Gradle 8.10.2, AGP 8.7.3, Kotlin 2.0.21, AOSP Android 15/API 35 x86_64 (AVD ShadeTask03API35). Рабочие .env/SQLite/HA не использовались.

| Web npm run build | Успешно |
| Android JVM | 15 passed: HTTP-классификация, неполный/невалидный receipt, прежние URL/HTTP/политика/UUID |
| Android instrumented | 37 passed: старые сценарии и новые миграции, backoff, reopen, 401/revision, 105 строк, атомарность receipt |

В instrumented-тесте SQLite-trigger намеренно ломает UPDATE результата. Проверено, что ошибка доходит до worker, row/UUID остаются прежними и следующий успешный повтор завершает доставку. Это проверяет сбой хранения после HTTP, а не только IOException.

[Системный сценарий](../../android/checks/check_delivery.py) использует свежий [Core-стенд](../../android/checks/core_server.py), отдельный синтетический издатель Ozon и loopback-прокси. На эмуляторе проверены:

1. Wi-Fi и data выключены: уведомление сохранено PENDING, attempts=0, Core пуст. После Wi-Fi on WorkManager доставляет без rebind listener.
2. Core сохраняет POST, прокси закрывает сокет без ответа: Android остаётся FAILED без completedAt. После force-stop/start повторяет тот же UUID; Core возвращает duplicate, число строк не растёт.
3. HTTP 401 останавливает всю очередь. Новое уведомление и ожидание 32 секунд не вызывают повтор HTTP. Сохранение настроек снимает паузу, обе записи доставляются.
4. HTTP 422 завершает одну строку как REJECTED, следующая доставляется. Нет падения приложения или тестового ключа в logcat.
5. Дополнительные 105 синтетических строк подготовлены SQL в копии debug Room при остановленном приложении в AVD. После возврата БД WorkManager отправляет несколько порций с лимитами 100 строк/45 секунд, каждая attempts=1. Core получает ровно 105 дополнительных записей, подтверждённые строки не пересылаются. Это проверка очереди/WorkManager, не массового системного перехвата.

Повторный прогон сценария TASK-11 на окончательном APK успешен: BigText/Inbox/ticker/только заголовок, фильтр, UUID/версии, force-stop, cancel/repost и 6 точных payload → Core. Сценарий адаптирован к Room v3 и ожиданию сети; отзыв доступа больше не используется как rebind (он законно очищает буфер); его исходные результаты/скриншоты в [отчёте TASK-11](task-11.md) остаются историческими для того коммита.

## Воспроизведение и границы

Команды и устройство стенда — [Android README](../../android/README.md#надёжная-доставка-и-повторы-task-12). Сначала завершить Gradle, затем запускать свежий Core и один UI Automator. Синтетические снимки/логи лежат в игнорируемом android/.gradle/task12-checks. Скрипт требует qemu=1 и отказывается заменять установленный Ozon; сбрасывает debug Shade в одноразовом AVD. Прокси закрывается, издатель удаляется, Wi-Fi/data восстанавливаются; после проверки остановить Core и эмулятор, убрать adb reverse. Тестовый Core и AVD после проверок остановлены, adb reverse отсутствует. SQL-подготовка не встроена в APK и не создаёт экспортированного интерфейса приложения.

Физического телефона/Pi нет. Не проверены Doze/экран off, особенности производителя, реальные уведомления, перезагрузка физического устройства, длительная эксплуатация и OEM backup. После пользовательского force-stop ОС не выполняет фоновые работы до запуска приложения. Периодические работы/JobScheduler могут задерживаться, данные истекают по политике хранения; абсолютной гарантии доставки при переполнении/потере callback нет. Retry-After HTTP 429 не интерпретируется отдельно: применяется общий ограниченный backoff. Для REJECTED ручного повтора/редактирования нет, UI журнала — TASK-13.

Основания выбора: официальные [WorkRequest/backoff/периодические работы](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work), [управление уникальной работой](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/manage-work), [NetworkCallback](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback), [релиз WorkManager 2.10.1](https://developer.android.com/jetpack/androidx/releases/work#2.10.1).

Следующая доступная работа — программная часть TASK-13: Android-журнал и сквозная проверка Android/Core/Web. Общий чекбокс этой задачи до аппаратного сценария оставить открытым.
