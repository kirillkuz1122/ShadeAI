## Что изменено

- Удалена недопустимая строка `[dev]` из requirements, зависимости приложения и разработки разделены. Прямые версии закреплены на проверенных; транзитивные зависимости полностью не зафиксированы. LLM-пакеты остаются отдельными.
- Settings читает обязательный `SHADE_API_KEY` из окружения или `.env`. Ключ должен содержать минимум 32 ASCII-символа без пробелов; значения-заглушки отклоняются. Старое имя `API_KEY` не используется.
- Добавлена `python -m app.setup`: локальная генерация ключа, запись `.env` через временный файл с правами 600, сохранение корректного существующего ключа и прочих настроек. Секрет не выводится. Неправильный произвольный ключ и символическая ссылка отклоняются.
- Сервер при ошибках настройки завершает запуск с объяснением и командой исправления. Значения ключа не включаются в текст ошибки или repr настроек.
- Dockerfile включает пустой `.env.example`; `.dockerignore` исключает локальные настройки, данные, модели и артефакты. Образ получает ключ при запуске через внешний файл.
- Добавлены тесты настройки/конфигурации и отказа с неверным Bearer; обновлены инструкции Core/README, раздел авторизации API и архитектура.

## Как повторить

Установка, локальный запуск, Docker с томом SQLite и команда тестов описаны в [core/README.md](../../core/README.md). Для HTTP-проверки используйте созданный ключ в заголовке Bearer на GET/POST `/api/v1/notifications`; без ключа или с другим значением ожидается 401. Проверки проводились на синтетических данных; рабочие `.env`, БД и HA не использовались. Временные окружение, скрипт и данные TASK-01 удалены после проверки; отчёт и код тестов остаются в репозитории.
