## Выбранный программный срез, 19 октября 2026

В работе. По умолчанию всё выключено; реальные замки/рабочая конфигурация не меняются.

PIN проверяет локальный Core (адаптер Shade Keypad), после чего один раз вызывает
`lock.unlock` через общий HA-аудит. Код не программируется в память замка и не
передаётся HA. Поэтому истечение/отзыв проверяются до команды, в том числе если
HA недоступен. Выключенный Core не принимает код. Это требует клавиатуры,
обращающейся к Core по локальной сети; обычная встроенная клавиатура Zigbee/Z-Wave
без такого адаптера этим контрактом не поддерживается.

Основание выбора: [стандартный HA lock](https://www.home-assistant.io/integrations/lock/)
предоставляет unlock, а [описание zwave_js set_lock_usercode](https://raw.githubusercontent.com/home-assistant/core/dev/homeassistant/components/zwave_js/services.yaml)
не обещает собственного срока действия. Удаление постоянного PIN серверным таймером
не гарантировало бы отзыв при выключении Core/потере связи.

Владелец отдельно проверяет событие доставки (качество TASK-18 пока 70%), явно
подтверждает выбранный замок и окно 1–15 минут. LLM самостоятельно доступ не выдаёт.
PIN из шести случайных цифр показывается владельцу один раз; в БД только HMAC,
метаданные и аудит. Повтор того же события/содержимого не создаёт новый код.
Клавиатура использует отдельный ограниченный токен, не ключ владельца. Попытки
ограничены и сохраняются в SQLite. Перед unlock фиксируется необратимое потребление
кода; timeout/restart не приводят к повторной команде. Отзыв после начала команды
не может вернуть уже отправленный unlock. Автоматического запирания двери нет.

Проверки, клиент и результаты будут записаны ниже по факту выполнения. Физический
замок/клавиатура, Pi, защищённая локальная сеть и аппаратная приёмка остаются открыты.

## Реализованная серверная основа

Миграция0013 AccessGrant/AccessGate, строгий owner/keypad API, HMAC PIN и fingerprint
истории, дедупликация ID/канонического payload, окно1–15минут, UTC+монотонный таймер,
пять попыток/60с и пять неверных→отзыв, предел1000/retention90дней. Scope включает
разрешённые замки/источники и ротацию обоих ключей. Restart active→revoked,
dispatching→unknown; unknown блокирует новые выдачи до ручного checked/revoke.
Сеть вне SQLite-транзакции, durable consumption до общего аудита/HA, без повтора.
PIN показывается только первым owner POST; после потери ответа его не восстановить,
можно отозвать. Просмотр/повтор не продлевает срок. Ротация ключа сбрасывает
пространство fingerprint; ни один старый grant не становится активным снова.

Ручной эмулятор `core/checks/keypad_client.py`: URL/отдельный токен через окружение,
PIN через getpass (не argv), только явный локальный IP, без DNS/proxy/redirect/retry.
Это диагностический клиент контракта, не прошивка аппаратной клавиатуры.

[Настоящий HTTP-стенд](task-26-core-loopback.json) PASS:2фиктивных unlock, отдельные
ключи/однократность/повтор уведомления/expiry/revoke/unknown/restart/privacy. Core и
HA-эмулятор общались по loopback; доставка и извлечение синтетические, native LLM
и аппаратуры нет. Все временные БД/ключи/серверы стенда удалены/остановлены.
