## Что изменено

- [conftest.py](../../core/tests/conftest.py) настраивает изолированную директорию и тестовые переменные до сбора тестов. Это необходимо, поскольку Settings и engine создаются при импорте. Рабочий `.env` не читается; одноимённые переменные окружения, включая варианты регистра, заменяются тестовыми.
- API-fixture создаёт отдельный файл SQLite на каждый тест, использует настоящее создание таблиц через lifespan и SQLite PRAGMA приложения. Подменяются engine и async_session; dispose выполняется на event loop TestClient. Ключи и адреса в fixtures синтетические.
- HA-клиент и health используют настоящий httpx-код с MockTransport. Mock проверяет адрес, Bearer и маршрут, позволяет моделировать успешный ответ, ConnectError и HTTP-ошибки; записывает запросы для проверки тела команды.
- Автоматическая fixture запрещает DNS и реальные TCP-соединения. Попытки обращения к сети и неожиданные запросы к mock проверяются в teardown, чтобы обработчик исключений приложения не скрывал ошибку теста.
- [test_api.py](../../core/tests/test_api.py) дополнен проверками доступности HA, успешного вызова сервиса и передачи параметров, отказа без авторизации и независимости БД. Проверка уведомлений теперь требует пустую исходную БД и ровно одну запись после приёма. Все тесты конфигурации/настройки из TASK-01 сохранены.

Рабочий код Core, контракт API, Android, веб и зависимости в этой задаче не менялись.

## Как повторить и продолжать

```bash
cd core
.venv/bin/python -m pytest -q
.venv/bin/ruff check app tests
```

Для новых API-тестов использовать fixtures `client`, `auth_headers`, `ha_mock`; новые HA-маршруты и ответы добавлять в mock. Fixtures подменяют общие настройки приложения, поэтому параллельные TestClient в одном процессе не предусмотрены. Аппаратную интеграцию HA проверять отдельно по TASK-06, не отключая сетевую защиту обычных тестов.
